# 수입관리 모듈 구현 명세서 (인증업무관리 앱 확장)

작성일: 2026-10-23
대상: 인증 업무 관리(로컬 웹앱)에 "수입관리" 메뉴 추가. 본인 전용, PC 사용, 세금 추정 포함.

## 0. 로컬 Claude Code에 붙여넣을 프롬프트

> 인증 업무 관리 앱 폴더에서 아래 명세서(수입관리-구현명세서.md)대로 "수입관리" 메뉴를 추가해줘.
> 먼저 기존 코드(메뉴 구조, 심사비관리 화면, `/api/data`, 다른 앱 DB의 위치 규칙)를 읽고 같은 방식과 스타일로 구현해줘.
> `fee.db`는 절대 수정하지 말고 읽기 전용으로만 사용해줘. 구현 전에 `fee.db` 스키마(PRAGMA table_info)를 확인하고, 심사비관리 대시보드의 집계 로직을 재사용해서 금액이 일치하는지 검증해줘.

## 1. 확정된 전제

| 항목 | 내용 |
|---|---|
| 심사비 DB | `C:\Users\USER\AppData\Local\KFQ_AuditApp\fee\data\fee.db` (SQLite) |
| 주요 테이블 | `fee_row`(CMS 지급현황 + 수기 심사수당), `trip_row`(출장비 + 수기 출장비), `fee_log`(확인 이력), `meta`(설정), `ev_pay`(일정관리 표시용 계산 결과) |
| 심사비 집계 기준 | 지급일자. 심사수당과 출장비는 분리 저장됨. 금액은 세전 |
| 심사비 API | 심사비관리 앱의 `/api/data` (포트는 앱 실행 상태에 따라 확인) |
| 출장비 | 실비로 수령. 3.3% 원천징수 대상 아님 (세무사 최종 확인 필요) |
| 심사수당 | 세전 금액. 3.3% 원천징수(소득세 3% + 지방소득세 0.3%)로 추정 |
| 신고 방식 | 세무사 신고. 경비율은 미확정이므로 입력값(설정)으로 둠 |
| 수입관리 DB | 별도 파일 `...\KFQ_AuditApp\income\data\income.db` (다른 앱 DB와 같은 위치 규칙) |
| 사용 환경 | 본인 전용, 로컬(127.0.0.1)에서만 접속 |

## 2. 설계 원칙

1. **`fee.db`는 읽기 전용.** SQLite를 `mode=ro`로 열고 어떤 쓰기도 하지 않는다. 심사비 수정은 심사비관리에서만 한다.
2. **심사비 집계를 다시 만들지 않는다.** 기존 심사비관리의 집계 함수/쿼리를 재사용해서 두 화면의 금액이 항상 같게 한다.
3. **수입 항목은 "자동(심사비)"과 "수동 입력"으로 구분**해서 보여주고, 자동 항목은 수정 불가로 표시한다.
4. **세법 수치는 코드에 박지 않고 연도별 설정 테이블로 분리**해서 세법 개정 시 설정만 바꾼다.
5. 세금 추정은 **참고용**임을 화면에 항상 표시한다. 신고는 세무사가 확정한다.
6. 인증서, 계좌 비밀번호, 주민등록번호는 저장하지 않는다.

## 3. 데이터 모델 (`income.db`)

```sql
-- 수동 입력 수입 (급여·상여·기타소득·금융소득 등)
CREATE TABLE income_item (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  paid_date     TEXT NOT NULL,          -- 지급일자 yyyy-mm-dd
  category      TEXT NOT NULL,          -- salary|bonus|lecture|consulting|writing|other|interest|dividend
  title         TEXT NOT NULL,          -- 항목명 (예: 10월 급여, ○○대학 강의)
  gross         INTEGER NOT NULL,       -- 세전 금액
  tax_income    INTEGER DEFAULT 0,      -- 원천징수 소득세
  tax_local     INTEGER DEFAULT 0,      -- 원천징수 지방소득세
  net           INTEGER,                -- 세후 실수령 (입력 또는 계산)
  income_type   TEXT,                   -- earned(근로)|business(사업)|other(기타)|interest|dividend
  source        TEXT DEFAULT 'manual',  -- manual|csv|api
  verified      INTEGER DEFAULT 0,      -- 홈택스 대조 완료 여부
  memo          TEXT,
  created_at    TEXT, updated_at TEXT
);

-- 연도별 설정 (세율표, 경비율, 공제, 목표 등)
CREATE TABLE settings (
  year INTEGER NOT NULL, key TEXT NOT NULL, value TEXT NOT NULL,
  PRIMARY KEY (year, key)
);

-- 금융소득 가져오기 중복 방지
CREATE TABLE import_hash (hash TEXT PRIMARY KEY, imported_at TEXT);

-- 연간 목표
CREATE TABLE goal (year INTEGER PRIMARY KEY, target INTEGER NOT NULL);
```

`settings` 주요 키: `trip_in_income`(출장비를 수입금액에 포함할지, 기본 0), `expense_rate`(필요경비율 %, 세무사 확인 후 입력), `expense_actual`(실제 경비 직접 입력), `withhold_rate_audit`(심사수당 원천징수율 기본 3.3), `tax_brackets`(종합소득세 구간표 JSON), `basic_deduction`(인적공제 등 소득공제 합계), `tax_credit`(세액공제 합계), `prepaid_tax`(기납부세액 보정), `fin_income_threshold`(금융소득 종합과세 기준 20,000,000).

## 4. 심사비 연동 (자동 항목)

- `fee.db`에서 지급일자 기준 월별로 **심사수당**(fee_row)과 **출장비**(trip_row)를 따로 집계한다.
- 집계는 심사비관리 대시보드와 같은 규칙을 쓴다(수기 입력 건 포함, 출장비는 심사기간이 맞는 심사 건에 합산하되 맞는 건이 없으면 출장비만 따로 집계).
- 수입관리 화면에서는 가상 행으로 표시한다.
  - 심사수당: category `audit_fee`, 세전, 추정 원천징수 3.3%
  - 출장비: category `audit_trip`, 실비, 원천징수 0
- `fee_row`에 실제 원천징수액이 있으면 그 값을 우선하고, 없으면 3.3%로 추정한다.
- 연동 검증: 심사비관리 대시보드와 연도·월 합계가 일치해야 한다. 예) 2026-10-15 확인 시점 2026년 합계 78,875,700원(심사수당 67,155,000 + 출장비 11,720,700). 이후 새 지급이 있으면 변동 가능하므로 두 화면을 서로 비교한다.
- 일정 미연결 건수(심사비관리 표시)를 수입관리 대시보드에도 경고로 보여준다.

## 5. 화면 구성 (상단 메뉴 "수입관리", 하위 탭)

1. **대시보드**
   - 기준(지급일자) · 연도 · 금액(세전/세후) 선택
   - KPI 카드: 올해 누적 수입, 전년 동기 대비, 월평균, 목표 달성률, 연말 예상 수입
   - 월별 누적 막대(소득원별 색 구분: 급여·상여·심사수당·출장비·기타·금융)
   - 소득원 구성 도넛, 전년 월별 비교선
   - 심사비 비중과 표준별 상위 3개(상세는 심사비관리로 링크)
   - 경고: 일정 미연결 N건, 홈택스 미대조 N건
2. **수입 입력/목록**: 급여·상여·기타소득 입력, 월 반복 항목 복사, 필터와 엑셀 내보내기, 자동 항목은 읽기 전용 표시
3. **금융소득**: 거래내역 CSV/엑셀 업로드 → "이자/배당/배당금" 적요 키워드로 후보 자동 분류 → 사용자 확인 후 저장, 중복 방지, 국내/해외 구분
4. **세금 추정**
   - 입력: 경비율 또는 실제 경비, 인적공제·소득공제·세액공제, 급여의 결정세액/기납부세액
   - 출력: 소득 구분별 합계 → 종합소득금액 → 과세표준 → 산출세액(+지방소득세 10%) → 기납부 원천징수 → **추가납부/환급 예상액**
   - 시나리오: 경비율을 바꿔 보는 민감도 표
   - 건강보험 영향 알림(소득·금융소득이 기준 근처일 때)
5. **설정**: 목표, 세율표, 경비율, 공제, 출장비 포함 여부, 연도별 보관

## 6. 세금 추정 로직

1. 소득 분류
   - 심사수당·인적용역 사업소득: 3.3% 원천징수 → 사업소득금액 = 수입금액 − 필요경비(경비율 또는 실제경비)
   - 급여·상여: 근로소득 → 연말정산 결과를 입력(결정세액, 기납부세액). 근로소득금액을 직접 계산하려면 근로소득공제표를 설정에 추가
   - 강의료 등: 일시적 인적용역은 기타소득(통상 필요경비 60% 의제, 기타소득금액 300만원 이하 분리과세 선택 가능), 반복·계속적이면 사업소득. **분류는 세무사 확인 후 항목별로 지정**하게 한다.
   - 출장비: 실비는 `trip_in_income`이 0이면 수입금액에서 제외(기본값), 1이면 포함. 신고 시 처리는 세무사에게 확인하도록 안내 문구를 넣는다.
2. 금융소득: 이자·배당 합계가 기준(2,000만원) 이하면 15.4% 원천징수로 종료, 초과 시 초과분을 종합소득에 합산(배당은 가산 및 배당세액공제 설정 필요).
3. 종합소득세: 종합소득금액 − 소득공제 = 과세표준 → 누진세율 적용(구간표는 `settings`의 JSON) → 세액공제 차감 → 산출세액. 지방소득세는 10%.
4. 정산: 산출세액 − 기납부세액(원천징수 합계 + 연말정산 결정세액) = 추가납부(+)/환급(−).

기본 종합소득세 구간표(2023년 이후 귀속, 구현 시 최신 세법으로 확인 후 입력):

| 과세표준 | 세율 | 누진공제 |
|---|---|---|
| 1,400만원 이하 | 6% | 0 |
| 1,400만 초과 ~ 5,000만 | 15% | 126만 |
| 5,000만 초과 ~ 8,800만 | 24% | 576만 |
| 8,800만 초과 ~ 1.5억 | 35% | 1,544만 |
| 1.5억 초과 ~ 3억 | 38% | 1,994만 |
| 3억 초과 ~ 5억 | 40% | 2,594만 |
| 5억 초과 ~ 10억 | 42% | 3,594만 |
| 10억 초과 | 45% | 6,594만 |

세법은 개정될 수 있으므로(예: 배당소득 분리과세 도입 논의) 구현 시점에 국세청/기재부 자료로 확인한다.

## 7. 단계별 구현

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1 | `income.db`, 메뉴·탭 틀, 수동 입력(급여·상여·기타), `fee.db` 읽기 전용 연동, 대시보드 | 심사비 월별 합계가 심사비관리와 일치 |
| 2 | 세금 추정, 설정(경비율·공제·세율표), 엑셀 내보내기, 목표 | 샘플 값으로 손계산과 일치 |
| 3 | 금융소득 CSV 가져오기와 분류, 홈택스 연간 합계 대조 | 중복 업로드 시 중복 등록 안 됨 |
| 4 | 연말 예상·전년 비교, 건강보험 기준 알림, 백업 | 앱 종료/재실행 후 데이터 유지 |

## 8. 비기능 요구

- 서버는 127.0.0.1에만 바인딩한다. 외부 노출 금지.
- `income.db`는 `fee.db`처럼 변경 시 `backup\`에 타임스탬프 백업(최근 30개 유지).
- 기존 UI(밝음/어두움 테마, 상단 메뉴 스타일, Noto Sans KR)를 그대로 따른다.
- 금액은 정수(원) 단위, 날짜는 yyyy-mm-dd(KST).
- 세금 추정 화면 상단에 "참고용 추정값, 신고는 세무사 확정" 문구 표시.

## 9. 세무사 확인 질문 목록 (신고 전)

1. 출장비(실비)를 수입금액에서 제외해도 되는지, 증빙 요건은 무엇인지
2. 심사수당의 소득 구분(사업소득)과 적용 경비율(단순/기준경비율 또는 장부)
3. 강의·컨설팅·번역·표준연구 수입의 소득 구분(사업소득 vs 기타소득)
4. 금융소득이 종합과세 기준에 근접할 때의 절세 방법
5. 건강보험·국민연금 영향 검토
