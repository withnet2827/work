# 치오 데일리 — 반려견 일상 기록·가족 공유 앱 기획안

- 문서 버전: v1.0 (초안)
- 작성일: 2026-10-07
- 대상: 반려견 '치오'와 가족 구성원 (소규모 비공개 앱)

---

## 1. 한 줄 정의

> **치오의 모든 기록(건강·병원·일기·사진)을 한 곳에 모으고, 가족 누구나 같은 정보를 보고 함께 채워 가는 우리 가족 전용 반려견 다이어리.**

## 2. 배경과 목적

| 구분 | 내용 |
|---|---|
| 문제 | 병원 영수증·진료기록이 흩어져 있고, 접종 시기·약 복용 여부를 가족끼리 매번 묻는다. 사진은 가족 단톡방과 각자 휴대폰에 흩어져 있다. |
| 목적 | ① 건강 정보의 단일 원천(Single Source of Truth) ② 일상의 추억 아카이브 ③ 가족 간 돌봄 분담·공유 |
| 성공 기준 | 가족 모두가 주 3회 이상 사용 / 병원 방문 시 앱 하나로 이력 설명 가능 / 접종·투약 일정 누락 0건 |
| 비목표 | 일반 사용자 대상 SNS, 수익화, 타 반려동물 커뮤니티 (우선 '우리 집 전용'으로 한정, 추후 확장 여지만 열어 둠) |

## 3. 사용자

| 역할 | 설명 | 권한 |
|---|---|---|
| 보호자(관리자) | 앱 개설자. 가족 초대·삭제, 데이터 내보내기 | 전체 |
| 가족 구성원 | 기록 작성·열람 | 작성/수정(본인 글), 열람 |
| 읽기 전용 | 조부모·친척·펫시터 등 | 열람만 (선택 항목만 공개 가능) |

핵심 시나리오
1. 산책 후 아이가 사진 1장과 함께 "오늘 산책 30분, 대변 정상"을 10초 안에 기록한다.
2. 병원에서 진료 후 영수증을 촬영해 첨부하고, 다음 접종일이 자동으로 달력·알림에 등록된다.
3. 아빠가 퇴근길에 "오늘 저녁 약 먹였나?"를 앱에서 확인한다 (엄마가 이미 체크함).
4. 연말에 '2026 치오 리포트'(사진·몸무게 변화·병원비)를 자동으로 받아 본다.

## 4. 기능 구성

### 4.1 한눈에 보는 기능 맵

```
치오 데일리
├─ 홈(오늘)        : 오늘의 치오, 해야 할 일, 가족 활동 피드, D-day
├─ 프로필          : 기본정보·등록정보·특이사항·응급카드
├─ 건강            : 병원기록 / 예방접종·예방약 / 투약 / 체중 / 증상
├─ 일기·일상기록   : 일기(글+사진) / 빠른 기록(산책·식사·배변 등)
├─ 앨범            : 사진·영상 DB (구글 드라이브 연동)
├─ 캘린더          : 일정·알림·기념일
├─ 가족            : 구성원·권한·댓글/반응·알림 설정
└─ 설정·백업       : 드라이브 연동, 내보내기(PDF/엑셀), 개인정보
```

### 4.2 프로필 (제안 항목 포함)

| 구분 | 항목 | 비고 |
|---|---|---|
| 기본 | 대표 사진, 이름(치오), 별명, 성별, 중성화 여부·일자, 생년월일/입양일, 견종, 모색, 체중(최신값 연동) | 나이는 자동 계산, 사람 나이 환산은 옵션 |
| 등록 | **동물등록번호**, 등록 방식(내장/외장 칩·인식표), 등록일, 등록 기관, 소유자 정보 | 등록증 사진 첨부 |
| 의료 기본 | 혈액형(선택), 알레르기, 만성질환, 복용 중인 약, 주의사항 | 응급카드에 노출 |
| 생활 | 사료 종류·급여량, 간식, 좋아하는 것/싫어하는 것, 성격, 훈련 가능한 명령어 | |
| 연락처 | 단골 병원(전화·길찾기), 보호자 연락처, 펫시터·미용실 | 1탭 전화 |
| **응급카드** | 사진·등록번호·연락처·알레르기를 한 화면으로 요약, QR/이미지로 저장·공유 | 실종 시 전단지 이미지 자동 생성(추가 제안) |

### 4.3 병원 기록 (핵심 모듈)

**입력 방식 3가지**
1. **직접 입력** — 병원명, 방문일, 증상/진단명, 처치·처방, 비용, 다음 방문일, 메모
2. **촬영** — 영수증·진료확인서·검사결과지를 카메라로 찍어 바로 첨부(자동 크롭·보정)
3. **파일 첨부** — 사진첩/PDF/드라이브 파일 선택 (여러 장 가능)

**기록 구조**: 진료 1건 = `방문 정보` + `첨부 문서 N개` + `처방(약) N개` + `비용 항목 N개`

| 기능 | 설명 | 단계 |
|---|---|---|
| 영수증 OCR | 영수증 촬영 시 병원명·일자·금액을 자동 추출 후 사용자 확인 | 2차 |
| 병원별/질환별 필터 | 병원, 기간, 진단명 태그, 비용 범위로 검색 | 1차 |
| 비용 통계 | 월·연도별 병원비, 항목별(진료·약·검사·예방접종) 비중 | 2차 |
| 진료 요약 PDF | 선택한 기간의 이력을 한 파일로 출력 → 병원 방문·전원·펫보험 청구용 | 2차 |
| 다음 일정 자동 등록 | 재진·접종 예정일 입력 시 캘린더·알림 자동 생성 | 1차 |
| 펫보험 청구 도우미 | 청구 대상 건 표시(청구 전/중/완료), 서류 묶음 | 3차(선택) |

### 4.4 예방접종 · 예방약 · 투약 · 체중

| 모듈 | 내용 |
|---|---|
| 예방접종 | 종합백신, 켄넬코프, 코로나, 광견병 등 접종 이력과 차기 예정일 (표준 일정 템플릿 제공) |
| 예방약 | 심장사상충, 외부·내부 기생충 — 월 단위 반복 알림, "투약 완료" 체크 시 누가 먹였는지 기록 |
| 투약 | 약 이름·용량·횟수·기간, 복용 체크리스트(가족 공유로 중복 투약 방지) |
| 체중 | 몸무게 그래프, 급격한 변화 시 알림, 체형(BCS) 메모 |
| 증상 일지 | 구토·설사·기침·절뚝거림 등을 사진·영상과 함께 기록 → 병원 방문 시 근거 자료 |

### 4.5 일기 · 일상 기록

| 구분 | 내용 |
|---|---|
| 일기 | 날짜별 글 + 사진/영상(여러 장), 기분 이모지, 날씨, 작성자 자동 기록. 가족 댓글·공감 |
| **빠른 기록** | 버튼 1~2번으로 기록: 산책(시간·거리), 식사, 간식, 물, 배변(상태 선택), 목욕, 양치, 미용, 훈련 |
| 산책 기록 | 시작/종료 타이머, GPS 경로(선택), 거리·시간 |
| 연속 기록 | '오늘 산책 완료 ✓' 같은 가족 공동 체크 — 중복 급여·미급여 방지 |
| 추억 되돌아보기 | "1년 전 오늘", 월간·연간 하이라이트 자동 생성 |
| 작성 도우미(선택) | 사진과 메모를 바탕으로 일기 초안을 AI가 제안(수정 후 저장) |

### 4.6 사진 · 영상 DB (구글 드라이브 연동)

**원칙: 원본은 구글 드라이브, 앱에는 '색인(메타데이터)+썸네일'만 저장**

| 항목 | 내용 |
|---|---|
| 폴더 구조 | `치오 데일리/` → `사진·영상/YYYY/MM/`, `병원서류/YYYY/`, `일기첨부/`, `백업/` 자동 생성 |
| 업로드 | 앱에서 촬영·선택 → 드라이브로 업로드, 앱은 파일 ID·촬영일·작성자·태그 저장 |
| 가져오기 | 기존 드라이브 폴더 연결, 휴대폰 사진첩에서 '치오' 얼굴 후보 일괄 가져오기(추가 제안) |
| 정리 | 날짜·태그(산책, 병원, 생일…)·작성자·즐겨찾기 필터, 앨범(여행·생일·성장) |
| 보기 | 타임라인/그리드, 영상 재생, 슬라이드쇼, 즐겨찾기 |
| 공유 | 가족 앱 내 공유 / 선택 앨범은 링크로 외부 공유(만료일 설정) |
| 용량 | 본인 드라이브 용량 사용 — 앱은 용량 현황과 원본/압축 선택 제공 |

> ⚠ 기술 유의: 드라이브 권한은 `drive.file`(앱이 만든 파일만 접근) 범위로 최소화하는 것을 권장합니다. 구성원별로 앱이 만든 파일 접근 권한이 분리되므로, 가족 간 공유 방식을 7장에서 정리했습니다.

### 4.7 캘린더 · 알림

- 일정 유형: 병원, 접종, 예방약, 투약, 미용, 생일·입양기념일, 사용자 일정
- 알림: 푸시(당일/1일 전/1주 전), 가족 지정 담당자 알림, 구글 캘린더 양방향 연동(옵션)
- 기념일 자동 생성: 생일, 입양 N일/N주년, 'D+1000' 등

## 5. 화면 구성(IA)과 UX 원칙

**하단 탭 5개**: 홈 · 일상(일기·빠른기록) · ➕ (빠른 추가) · 앨범 · 건강
(프로필·가족·설정은 홈 상단 아이콘)

UX 원칙
1. **3탭 이내 기록**: 가운데 ➕ 버튼에서 사진/산책/식사/배변/병원/메모를 즉시 선택
2. **가족 모두가 쓰기 쉬운 크기**: 글자 크기 조절, 큰 버튼 (어르신 구성원 고려)
3. **오프라인 허용**: 산책 중 통신이 불안정해도 기록 후 자동 동기화
4. **따뜻한 톤**: 치오 사진을 중심으로 한 홈, 부드러운 색상, 불필요한 숫자 최소화

홈 화면 구성(예)
1. 치오 대표 사진 + 나이·D-day(생일까지)
2. 오늘 할 일(약, 예방약, 산책) 체크
3. 가족 활동 피드 · 1년 전 오늘
4. 다가오는 일정

## 7. 기술 구성안

### 7.1 권장 아키텍처

| 계층 | 권장 | 이유 |
|---|---|---|
| 앱 | **Flutter** (iOS·Android 동시) 또는 PWA(MVP) | 카메라·푸시·위젯 지원, 가족 기기 혼용 대응 |
| 인증 | 구글 로그인 (Firebase Auth) | 드라이브 연동과 계정 일원화 |
| 데이터 | Firebase Firestore (또는 Supabase) | 실시간 동기화, 오프라인 캐시, 소규모 비용 거의 무료 |
| 파일 | **Google Drive API** (원본) + 썸네일 캐시 | 요구사항: 사진 파일 구글 드라이브 연동 |
| 알림 | FCM 푸시 + 로컬 알림 | 투약·접종 알림 |
| OCR(2차) | 온디바이스 ML Kit 또는 클라우드 OCR | 영수증 자동 입력 |

### 7.2 구글 드라이브 연동 방식 (결정 필요)

| 방식 | 구조 | 장점 | 단점 |
|---|---|---|---|
| **A. 각자 드라이브 + 공유(권장)** | 구성원이 올린 파일은 본인 드라이브의 '치오 데일리' 폴더에 저장, 앱이 가족에게 읽기 권한 부여 | 용량 분산, 권한 단순, 본인 사진 통제 | 구성원 탈퇴 시 파일 소유 이전 필요 |
| B. 관리자 드라이브 1곳 | 모든 파일을 관리자 드라이브에 저장 | 한 곳에서 관리·백업 | 관리자 용량 집중, 가족 권한(파일 접근) 구성이 복잡 |
| C. 앱 스토리지(Firebase) + 드라이브 백업 | 앱 저장소가 주, 드라이브는 정기 백업 | 속도·안정성 최고 | 비용 발생, '드라이브 연동' 의도와 다소 다름 |

→ **MVP는 A안**, 속도 문제가 생기면 썸네일/미리보기를 앱 저장소에 두는 하이브리드로 보완.

### 7.3 보안·개인정보

- 가족 단위 데이터 격리(접근 규칙으로 Family 외 열람 불가), 전송·저장 암호화
- 드라이브 권한 최소 범위, 연동 해제 시 앱 내 색인만 삭제하고 원본은 유지
- 위치(산책 GPS)·소유자 연락처는 외부 공유 기본 제외
- 전체 데이터 **내보내기(JSON/엑셀/PDF)** 제공 — 서비스 종료 시에도 기록 보존
- 영수증에는 결제 정보가 포함될 수 있으므로 외부 공유 링크는 기본 비활성

### 7.4 비용 개요 (가족 5인 이하 기준 추정)

- 앱 호스팅·DB·푸시: 무료 구간 내 운영 가능 (Firebase 무료 요금제 범위)
- 드라이브: 기존 구글 계정 용량 사용 (부족 시 Google One)
- 스토어 등록: 구글 플레이 일회성 약 25달러, 애플 개발자 연 99달러 (가족 간 배포는 TestFlight/내부 테스트로 대체 가능)

## 10. 확정이 필요한 사항 (질문)

1. **사용 기기**: 가족의 휴대폰이 모두 안드로이드인가요, 아이폰이 섞여 있나요?
2. **가족 인원**과 연령대(큰 글씨·단순 UI 필요 여부)
3. **구글 드라이브 방식**: 각자 드라이브(A안) vs 관리자 한 곳(B안)
4. **동물 수**: 치오 1마리 전용인가, 추후 다른 반려동물 확장 가능성이 있는가
5. **개발 방식**: 직접 개발/외주/노코드(예: Glide·AppSheet로 빠른 시제품) 중 어떤 방향인가
6. **우선순위**: 위 기능 중 '이것만큼은 먼저'인 것 3가지
7. 기존 제미나이 기획안과 겹치거나 꼭 유지할 항목이 있는가
